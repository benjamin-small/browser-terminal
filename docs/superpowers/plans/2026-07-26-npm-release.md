# npm Release Plan — `@benjamin-small/browser-terminal` 0.1.0

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the library to npm as `@benjamin-small/browser-terminal@0.1.0`, Apache-2.0, with a tarball proven to work in a project that is *not* this workspace.

**Architecture:** No source changes. This is packaging: a scoped rename across 11 sites, the legal and discovery metadata npm needs, a publish guard so a stale `dist/` can never ship, and an out-of-workspace install proof.

**Tech stack:** npm workspaces, `just` (cargo + wasm-bindgen + wasm-opt), TypeScript, GitHub Actions.

---

## Context an engineer needs

`packages/browser-terminal` is the only publishable package; `packages/demo`, `demo-react`, `demo-svelte` are private workspace consumers of it and are never published.

**Three facts that shape everything below:**

1. **The unscoped name is taken.** `browser-terminal` on npm is an unrelated 2022 package (v0.0.2). Scoping is mandatory, not stylistic.
2. **`packages/browser-terminal/src/wasm/` is gitignored** — it is generated by `just wasm` (cargo → wasm-bindgen → wasm-opt). The package's own `npm run build` only runs `tsc` and then `cp -R src/wasm dist/wasm`. So `npm publish` from a clean checkout would ship a **missing or stale `.wasm`** and the failure is silent at pack time. This is the single biggest release hazard.
3. **Workspace linking hides packaging bugs.** Every current test imports the library through the npm workspace symlink, which resolves files `npm publish` may never include. Only installing the real tarball outside the repo proves `exports`, `files`, and the `new URL('./wasm/…', import.meta.url)` resolution actually work.

**Decisions already made (do not relitigate):** scope `@benjamin-small` (org exists); license Apache-2.0; version 0.1.0.

**Not yours to do — these need the human:** `npm login`, creating or managing the npm org, and setting the `NPM_TOKEN` GitHub secret. Never handle credentials. The final `npm publish` is gated on explicit human go-ahead (see Task 7).

## Task 5: A publish guard, so a stale dist cannot ship

**Files:** `packages/browser-terminal/package.json`

This is the task that prevents the worst outcome: a published package whose `.wasm` is missing, stale, or built from different Rust source than the TypeScript beside it.

- [ ] **Step 1: Add the guard scripts**

```json
    "prepublishOnly": "node scripts/check-publishable.mjs",
```

- [ ] **Step 2: Write `packages/browser-terminal/scripts/check-publishable.mjs`**

It must **fail loudly** rather than fix things silently. Assert all of:

1. `dist/index.js`, `dist/index.d.ts` and `dist/wasm/bterm_wasm_bg.wasm` exist.
2. The `.wasm` is non-trivial (> 100 KB — a truncated or placeholder file is the failure mode we are guarding).
3. `dist/wasm/bterm_wasm_bg.wasm` is **newer than every tracked file under `crates/`**. This is the stale-build check; compare `mtime` against the newest `crates/**/*.rs`. On failure, print the offending source file and the exact remedy: `just build`.
4. `git status --porcelain` is empty. Publishing from a dirty tree makes the tarball unreproducible from any commit.

Each failure exits non-zero with a message naming the fix. No auto-rebuild: a publish command that quietly rebuilds is a publish command whose output nobody reviewed.

- [ ] **Step 3: Prove the guard bites**

This is the whole point of the task — a guard that never fires is decoration.

```bash
# 3a. Stale wasm: touch a Rust source so it post-dates the build.
touch crates/bterm-core/src/lib.rs
cd packages/browser-terminal && npm run prepublishOnly
```
Expected: **fails**, naming `crates/bterm-core/src/lib.rs` and telling you to run `just build`.

```bash
# 3b. Missing wasm.
just build && mv packages/browser-terminal/dist/wasm/bterm_wasm_bg.wasm /tmp/w.wasm
cd packages/browser-terminal && npm run prepublishOnly
```
Expected: **fails** on the missing binary. Restore it afterwards.

```bash
# 3c. Clean and built: passes.
just build && cd packages/browser-terminal && npm run prepublishOnly
```
Expected: **passes**.

Report all three outputs verbatim. If any of 3a/3b passes, the guard is broken — fix it before continuing.

- [ ] **Step 4: Commit**

```bash
git add packages/browser-terminal/package.json packages/browser-terminal/scripts/check-publishable.mjs
git commit -m "Refuse to publish a stale, incomplete, or uncommitted build

src/wasm is gitignored and the package's own build only copies it, so a
publish from a fresh checkout would ship a missing or stale binary and
say nothing. The guard fails loudly instead, and its stale check is
mtime against crates/, which is the case that would otherwise ship
TypeScript built against different Rust."
```

## Task 6: Prove the tarball works outside this workspace

**Files:** none committed — this is verification.

Every existing test resolves the library through the workspace symlink. That symlink resolves files the tarball may not contain. This task is the only thing standing between us and a published package that fails on `npm install`.

- [ ] **Step 1: Build and pack for real**

```bash
just build
cd packages/browser-terminal && npm pack
```
Note the tarball path and the reported size (~231 kB packed at last measurement).

- [ ] **Step 2: Inspect what is actually inside**

```bash

```
Assert present: `package/dist/index.js`, `package/dist/index.d.ts`, `package/dist/wasm/bterm_wasm_bg.wasm`, `package/dist/wasm/bterm_wasm.js`, `package/README.md`, `package/LICENSE`, `package/package.json`.
Assert **absent**: anything under `package/src/`, `package/scripts/`, `tsconfig.json`.

If `LICENSE` is missing, npm did not pick it up from the repo root — copy it into `packages/browser-terminal/` and re-pack.

- [ ] **Step 3: Install it into a scratch app outside the repo**

Use the scratchpad, **not** a directory inside the workspace (npm would resolve the workspace copy and defeat the test):

```bash
mkdir -p /tmp/rel-check && cd /tmp/rel-check
npm create vite@latest app -- --template vanilla-ts
cd app && npm install
npm install /Users/bsmall/dev/browser-terminal/packages/browser-terminal/browser-terminal-0.1.0.tgz
```

- [ ] **Step 4: Use it, and build it**

Replace `src/main.ts` with a minimal real usage — `BrowserTerminal.create()`, one `registerCommand`, and one `run()` — then:

```bash

```
Expected: both clean. A `tsc` failure means the shipped `.d.ts` files are wrong; a Vite build failure usually means the wasm `new URL(...)` asset was not emitted.

- [ ] **Step 5: Run it in a browser and prove the wasm loads**

Serve the built app and open it in the Browser pane. Then, in the page, assert the real end-to-end path:

```js

```

The wasm loading over HTTP from a *published layout* is the thing no existing test covers. Confirm no 404 for `bterm_wasm_bg.wasm` in the network log, and no console errors.

- [ ] **Step 6: Report**

State the tarball size, the file list verdict, and the browser result. Then delete `/tmp/rel-check` and the `.tgz`. **If any step fails, stop — do not proceed to Task 7.**

## Task 8: Tag, changelog, and GitHub release

**Files:** create `CHANGELOG.md`; create `.github/workflows/release.yml`

- [ ] **Step 1: Write `CHANGELOG.md`**

Keep-a-Changelog format. The 0.1.0 entry is the first public release, so describe capability rather than diffs: structured-value pipes; commands in Rust or TypeScript; the tmux surface; docked/floating Shadow-DOM panel; the three output channels with data structurally separated from diagnostics; streaming pipes; progressive rendering; the buffered writer API with its control-character allowlist. Close with a **Known limitations** section matching the package README.

- [ ] **Step 2: Tag and release**

```bash
git tag -a v0.1.0 -m "v0.1.0 — first npm release"
git push origin v0.1.0
gh release create v0.1.0 --title "v0.1.0" --notes-file CHANGELOG.md
```

- [ ] **Step 3: Add a tag-triggered publish workflow**

Create `.github/workflows/release.yml`, triggered on `push: tags: ['v*']`. It must install the Rust toolchain, the `wasm32-unknown-unknown` target, the **pinned** `wasm-bindgen-cli` (`=0.2.126` — must match `crates/bterm-wasm/Cargo.toml`, see the existing `ci.yml` for the pattern), and `binaryen` for `wasm-opt`; then run the full gate (`cargo test --workspace`, `just test-wasm`, `just typecheck`, Playwright) before `npm publish --provenance --access public`.

`--provenance` requires `permissions: id-token: write`. It gives the package a verifiable link back to the commit and workflow that built it — worth having from the first release, since it cannot be added retroactively to 0.1.0.

This needs an `NPM_TOKEN` repository secret (a granular automation token). **The human creates and sets it** — do not ask for the value or handle it.

- [ ] **Step 4: Commit**

```bash
git add CHANGELOG.md .github/workflows/release.yml
git commit -m "Record the 0.1.0 release, and publish the next one from CI"
```
