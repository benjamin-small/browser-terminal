# v0.5.0 — Browser filesystem by default

## Changes

- `BrowserTerminal.create()` automatically mounts writable OPFS at `/scratch`,
  starts sessions there, and displays a directory-aware prompt. `pwd`, `cd`,
  `ls`, `cat`, `read-bytes`, `edit`, path completion, the text editor, and file
  redirection are ready before creation resolves. No host commands or folder
  picker are required. `bt.filesystem` exposes the default adapter.
- Missing or rejected OPFS access produces a warning in the terminal and
  JavaScript console. Creation still succeeds with the core shell, without
  installing filesystem commands; `bt.filesystem` is `null`.
- JSON and string commands use `to-json`, `from-json`, `str-upcase`, and
  `str-downcase` in help and command completion. Spaced names remain callable
  compatibility aliases, including their flags and argument completion.
- The demo supplies an Enable writes button for each connected local folder.
  Shell redirection can create files after permission is granted, without
  opening the editor first. Permission requests stay inside the user gesture.

## Upgrade

Automatic filesystem setup is a change from v0.4.0. Hosts that already install
an adapter or own commands such as `ls` must use
`BrowserTerminal.create({ filesystem: false })` before their existing setup.
This also disables automatic storage access and its warnings. Alternatively,
use `bt.filesystem` to add mounts to the default adapter. Custom redirect hooks
can still replace the default handler.

Importing the package alone does not initialize the terminal or access storage.
The automatic mount uses the origin's OPFS root and creates no sample files.
The demo retains its existing `browser-terminal-demo` subdirectory. OPFS belongs
to the origin and browser profile and is subject to quota, eviction, and removal
when site data is cleared. Native local folders still require explicit mounting
and browser permission; additional mounts remain read-only by default.

## Validation and coverage

- Rust formatting, Clippy, and 279 native Rust tests passed.
- 48 WASM boundary tests passed against the rebuilt v0.5.0 core.
- TypeScript package build and demo type checking passed.
- 24 filesystem contract tests and 51 Chromium browser tests passed.
- New browser coverage includes automatic setup without custom commands,
  reads and redirects, editor cleanup, new-session directories, persistence
  across terminal recreation, both warning destinations for missing/rejected
  OPFS, and the explicit opt-out.
- The release workflow checks WASM boundaries and verifies the packed package
  from a clean checkout before publishing the exact tested tarball.

Native local-folder saves and native Edge/Safari UI were not manually rechecked
for this release. Local-folder write permission flows are covered by Chromium
browser tests with controlled directory handles; real OPFS I/O is exercised.
Firefox and WebKit were not rerun for v0.5.0. OPFS API presence alone does not
imply access will succeed; failed access uses the warning-and-core-shell path.
