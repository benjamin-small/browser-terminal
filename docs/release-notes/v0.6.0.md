# v0.6.0 — Host messages and quieter consoles

## Changes

- `bt.print(text, { pane? })` writes one or more host lines above a pane's
  prompt (the active pane by default), then redraws the prompt with any
  half-typed input and the cursor where it was. Styling is kept; sequences that
  clear the screen or move the cursor off the line are removed. While a command
  runs in the pane, the text is queued and appears above the prompt when the
  command finishes or is interrupted. Programmatic `run()` calls do not hold it
  back. An unknown or non-integer pane throws a `RangeError`, and `print()`
  throws after `dispose()`.
- `logLevel` (`'silent' | 'error' | 'warn' | 'info' | 'debug'`, default
  `'warn'`) and an optional `logger` on `CreateOptions`, plus
  `bt.setLogLevel()` and `bt.logLevel`. All of the library's console output
  goes through them, including the Rust core's, which no longer writes to the
  console itself.
- A `.wasm` served without the `application/wasm` MIME type now warns once
  through the logger, rather than through wasm-bindgen's own `console.warn`.
- The OPFS-unavailable warning uses `print()`, so it redraws the real prompt
  instead of a hard-coded one, and it goes through the logger.

## Upgrade

**Changed default:** when a host command or redirect handler throws, its stack
is no longer sent to `console.error`. The pane still shows the error, and
`run()` still rejects with its message; the stack is logged at `'debug'`.
Pass `logLevel: 'debug'` to get it back. All other output is unchanged at the
default level: re-registering a command warns, unavailable storage warns, and
a failed cleanup listener is an error.

Hosts that showed banners by sending `paneOutput` events to the private pane
manager, then clearing and resetting the prompt to force a redraw, can replace
that with `bt.print(line)`. The private field and event shape are not part of
the public API.

A custom `logger` can be called from inside a running command, so it must not
call `dispose()`.

## Validation and coverage

- Rust formatting, Clippy, and 284 native Rust tests passed.
- 57 WASM boundary tests passed. New ones cover printing over partial input,
  queueing while a command runs and flushing on completion and Ctrl-C, and the
  cases where a prefix-key command, a pasted second line, or a Ctrl-C+command
  chunk finishes while another run is still writing to the pane. Others check
  that the core sends its log lines to the host as `log` events at the right
  levels and never calls the console.
- 29 Node tests (filesystem contract and the log-level filter) and 56 Chromium
  browser tests passed. Browser coverage includes printed banners landing
  directly above the restored input line, invalid pane ids, a clean console at
  the default level, `'debug'` with a custom logger, `'silent'` with storage
  unavailable, the cleanup-failure path, and a wrong `.wasm` MIME type.

Firefox and WebKit were not rerun for v0.6.0. Input that wraps past the pane
width is only cleared on its last row when the prompt is redrawn after
`print()`; `setPrompt()` redraws already behave this way.
