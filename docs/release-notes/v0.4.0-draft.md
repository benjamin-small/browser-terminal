# v0.4.0 — Browser files and editing

Status: implemented release candidate, unreleased.

## Changes

- Optional filesystem adapter with user-selected local directory mounts and OPFS
  scratch storage. `pwd`, `cd`, structured `ls`, `cat`, and `read-bytes` work with
  session-scoped directories and bounded I/O.
- Optional `edit` integration and a lightweight DOM editor with Save, Reload,
  permission requests, export, dirty-buffer handling, UTF-8/BOM/CRLF preservation,
  and best-effort detection of external changes.
- Explicit file redirection and staged byte writes with commit/abort semantics.
  Writes serialize across mount aliases and preserve bytes outside patched ranges.
- Experimental bounded null/zero devices and fixed-capacity file-backed blocks.
- Owned command registration and lifecycle subscriptions for adapter cleanup.
- Filesystem contract tests and the complete browser suite now gate CI/releases.
  Existing Rust formatting was normalized in a separate commit.

## Upgrade

Existing applications retain their behavior. Install the filesystem explicitly
from `@benjamin-small/browser-terminal/filesystem`; the optional editor is a
separate `/filesystem/editor` import. Command collisions fail without replacing
host commands. Mounts default to read-only; write access requires both host
opt-in and browser permission. Redirects are installed separately.

See the [filesystem guide](../filesystem.md) for working examples, the byte API,
and limits. Defaults: 8 MiB buffered reads/write chunks, 2 MiB editor files,
64 KiB streamed chunks. Block and device APIs are experimental.

Writes commit on successful stream close and cannot roll back afterward. Creating
an entry may leave an empty file if writing subsequently fails. Conflict checking
cannot eliminate races with external applications. OPFS is origin-private and
subject to quota/eviction. Generic redirects collect before the adapter's size
check; use the byte API for large transfers.
