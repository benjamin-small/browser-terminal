# v0.4.0 — Browser files and editing

## Changes

- Optional filesystem adapter with user-selected local directory mounts and OPFS
  scratch storage. `pwd`, `cd`, structured `ls`, `cat`, and `read-bytes` work with
  session-scoped directories and bounded I/O.
- Local-folder connections default to `/mnt/<folder-name>` with numeric suffixes
  for duplicate names. `/mnt` is navigable even when empty; browser storage
  remains at `/scratch`. Hosts can use `mountLocal()` or explicit nested mounts.
- The connection UI reports pending selection, cancellation, and picker errors;
  failed navigation rolls back a newly created mount and allows another attempt.
- Optional `edit` integration and a lightweight DOM editor with Save, Reload,
  permission requests, export, dirty-buffer handling, UTF-8/BOM/CRLF preservation,
  and best-effort detection of external changes.
- Explicit file redirection and staged byte writes with commit/abort semantics.
  Writes serialize across mount aliases and preserve bytes outside patched ranges.
- Experimental bounded null/zero devices and fixed-capacity file-backed blocks.
- Owned command registration and lifecycle subscriptions for adapter cleanup.
- Tab completion for built-in and registered command names, including multiword
  commands and positions after pipes/semicolons. Ambiguous names expand a shared
  prefix or list candidates. Argument completion includes signature-defined flags
  and booleans, filesystem paths, redirect targets, and host-provided choices.
  Path suggestions quote shell punctuation and discard stale asynchronous results.
- The demo prompt displays each session's working directory. Dynamic prompt
  callbacks and `refreshPrompt()` let other hosts display their own state.
  A standalone `/` now works as a command argument, including `cd /` and `ls /`.
- The demo starts in writable `/scratch` browser storage without permission
  prompts, with file redirects enabled and saved files restored on reload.
  Local folders are optional and request read access when connecting; missing
  write permission does not block browsing. The editor requests write access
  separately when needed and
  hides permission controls when access is already granted. Hosts can configure
  the adapter's default session directory with `initialDirectory`.
- Filesystem contract tests and the complete browser suite now gate CI/releases.
  Existing Rust formatting was normalized in a separate commit.

## Upgrade

Existing applications retain their behavior. Install the filesystem explicitly
from `@benjamin-small/browser-terminal/filesystem`; the optional editor is a
separate `/filesystem/editor` import. Command collisions fail without replacing
host commands. Mounts default to read-only; write access requires both host
opt-in and browser permission. Redirects are installed separately.

See the [filesystem guide](../filesystem.md) for working examples, the byte API,
and limits. Defaults: 8 MiB buffered reads/write chunks, 2 MiB editor files,
64 KiB streamed chunks. Block and device APIs are experimental.

Writes commit on successful stream close and cannot roll back afterward. Creating
an entry may leave an empty file if writing subsequently fails. Conflict checking
cannot eliminate races with external applications. OPFS is origin-private and
subject to quota/eviction. Generic redirects collect before the adapter's size
check; use the byte API for large transfers.

Native local save and native Edge/Safari verification remain unverified coverage
for this release. OPFS save/reopen and conflict handling are verified by browser tests. Native picker
support must be feature-detected; do not infer it from OPFS support.
API presence alone is insufficient: embedded browsers may expose the picker
without completing the native permission flow. The demo's error message now
explains the external-browser workaround and retains the original browser error.
